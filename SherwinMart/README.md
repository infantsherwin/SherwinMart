# SherwinMart

A multi-seller e-commerce marketplace built with Java Servlets, JDBC, and Apache Tomcat.
Sellers list products; buyers browse, search, add to cart, and check out via a mock
payment step; an admin moderates users, listings, and orders.

Built for Anna University R2025, Semester 3 — Java capstone project.
Checkpoint window: **Jul 27 – Oct 10, 2026**.

> This repository currently implements **Week 1 & Week 2** of the timeline (Section 6):
> authentication, the DAO/service/controller layers, and the full browse → cart → order
> flow (F1–F6). Seller/admin dashboards, reviews (F8), search polish, and the AI chatbot
> (O4) are scoped for later weeks per the timeline below.

## Problem statement

Buyers need a simple place to discover and purchase products from many independent
sellers, without each seller needing their own storefront. SherwinMart provides shared
browsing/search, a cart, and checkout, while giving sellers listing management and order
visibility, and giving admins oversight of the whole marketplace.

## Architecture

```
Browser (HTML/CSS/vanilla JS + fetch)
        |
Filter layer  -> EncodingFilter, AuthFilter (session check on /api/v1/**)
        |
Servlets      -> AuthServlet, ProductServlet, CartServlet, OrderServlet, HealthServlet
        |
Service layer -> UserService, ProductService, CartService, OrderService
        |          (business rules & validation — no JDBC here)
DAO layer     -> UserDAO, ProductDAO, CartDAO, OrderDAO (+ Impl)
        |          (ALL SQL lives here, PreparedStatement only)
Connection Pool -> HikariCP, via DataSourceListener (Singleton, startup/shutdown)
        |
H2 Database (embedded locally / server mode when deployed)
```

Package layout (`com.sherwin.sherwinmart`):

```
controller/  — thin servlets, no SQL, no business logic
service/     — business rules, orchestration, transactions
dao/         — interfaces + dao/impl/ JDBC implementations
model/       — POJO entities
dto/         — request/response shapes (e.g. UserResponseDTO never exposes passwordHash)
filter/      — AuthFilter, EncodingFilter
listener/    — DataSourceListener (connection pool lifecycle)
util/        — PasswordUtil, ValidationUtil, JsonUtil
exception/   — ValidationException, NotFoundException, AuthException, ConflictException
```

Design patterns used (Section 12): **DAO** (data access abstraction), **Front
Controller**-style per-resource servlets, **Singleton** (`DataSourceListener` owns the one
HikariCP pool), **Builder** (`UserResponseDTO.Builder`). Factory/Strategy hooks are left
for the AI chatbot provider (`ChatProvider` interface, Week 9) and are not yet needed
elsewhere in the current scope.

## Database schema

See `src/main/resources/schema.sql` (applied automatically on startup) and
`db/migrations/V1__init_schema.sql`. Tables: `users`, `products`, `orders`,
`order_items`, `cart_items`, `reviews` — matching Section 4 exactly, with every foreign
key indexed, `email` unique, monetary columns `DECIMAL(10,2)`, and `created_at` on every
table.

## API (Section 13 conventions)

All endpoints are under `/api/v1/...` and return the fixed envelope
`{ "success": bool, "data": ..., "error": { "code", "message" } | null }`.

| Endpoint | Method | Notes |
|---|---|---|
| `/api/v1/auth/register` | POST | Buyer/Seller only — admin is seed-only (F1) |
| `/api/v1/auth/login` | POST | Regenerates session ID on success |
| `/api/v1/auth/logout` | POST | Invalidates session |
| `/api/v1/auth/me` | GET | Current session user |
| `/api/v1/products` | GET | Public browse/search: `?q=&category=`; `?id=`; `?mine=true` (seller) |
| `/api/v1/products` | POST/PUT/DELETE | Seller-only listing CRUD (F2) |
| `/api/v1/cart` | GET/POST/PUT/DELETE | Buyer cart (F4) |
| `/api/v1/orders` | POST | Place order from cart, requires `mockPaymentConfirmed: true` (F5) |
| `/api/v1/orders` | GET | `?asSeller=true` for incoming orders; `?id=&items=true` for line items (F6) |
| `/api/v1/health` | GET | `{ status: "UP", db: "UP" }` |

## Setup instructions

See [`CONTRIBUTING.md`](CONTRIBUTING.md) for full clone-to-running-instance steps. Quick
version:

```bash
git clone <your-repo-url> && cd SherwinMart
mvn clean verify
mvn clean package
cp target/sherwinmart.war $CATALINA_HOME/webapps/
$CATALINA_HOME/bin/catalina.sh run
```

Then visit `http://localhost:8080/sherwinmart/`. The app runs out of the box against an
in-memory H2 database seeded with a demo admin, seller, and buyer account (password:
`password` for all three — see `src/main/resources/seed.sql`). For a persistent
deployment, point `config.properties` at an H2 server-mode instance per `.env.example`.
